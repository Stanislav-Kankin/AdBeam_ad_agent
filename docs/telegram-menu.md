# Меню Telegram

## Состояние данных

В карточке клиента доступен раздел «Состояние данных». Он показывает последние 30
завершённых дней: количество свежих дневных снимков отдельно для Direct и Метрики,
пропуски, последний сохранённый срез и его ограничения, завершённость загрузки
разрезов, выбранные счётчики и цели. Нулевой трафик считается полученными данными.
Экран читает базу; он не проверяет доступы в API заново. «Обновить экран» повторно
читает состояние, «Проверить клиента» открывает выбор периода для обычного анализа.
Число недостающих дней не является размером очереди; срок её завершения не известен.

## KPI проекта

Администратору в карточке клиента доступна кнопка «🎯 KPI проекта». В ней:

- главный KPI: CPA, ДРР, конверсии или «Авто». «Авто» означает ДРР при заданном
  целевом ДРР, иначе CPA при выбранных основных целях;
- допуск (статистическая погрешность): ±3%, ±5% или ±10%, по умолчанию 3%;
- целевой CPA и целевой ДРР вводятся числом (`2500`, `2 500`, `2500,5`);
  `0` убирает цель.

Цвет статуса клиента считается по главному KPI. Если он в пределах допуска или
улучшился, изменения расхода, CPC и CR остаются в отчёте как контекст и не делают
клиента жёлтым. Без целевого CPA бот всё равно сигнализирует о росте CPA больше
допуска. Профиль хранится в `client_preferences.targets`, переживает перезапуск и
не сбрасывает собранное хранилище данных: сырые снимки от KPI не зависят.

## Карточка отчёта

Одиночная проверка отвечает карточкой: статус и главный KPI, короткий вывод,
показатели в формате «изменение · сейчас / было», блок «Требует внимания» с
конкретными кампаниями и одна строка о полноте данных. Изменения в пределах допуска
помечаются «стабильно». DeepSeek пишет только вывод из 1–2 предложений, структура и
числа формируются backend. Под карточкой кнопки «📈 Кампании» (вклад кампаний, CPA
сейчас и раньше), «👥 Аудитория» и «⚙️ Технические данные».

## Пользователи

Администратору доступно `/menu` → «Пользователи» → «Добавить по Telegram ID».
После ввода положительного числового ID пользователь может написать боту `/start`
в личном чате. Ему доступны текущие клиенты, видимые добавившему администратору;
клиенты, появившиеся позже, автоматически не добавляются. Добавление того же ID
повторно обновляет этот набор. Права хранятся в таблице `bot_users`, отдельно для
production и mock, вместе с ID администратора и временем изменения.

Кнопка «Удалить» отзывает доступ, включая доступ из разрешённых групп, даже если
ID ранее был указан в `.env`. «Добавить снова» восстанавливает его. Запущенные
ранее задачи могут завершиться. Администраторы `TELEGRAM_ADMIN_USER_IDS` защищены
от удаления через меню; назначение администраторов остаётся в `.env`.
Группы сохраняют свои настройки доступа: если `TELEGRAM_ALLOWED_USER_IDS` пуст,
участники разрешённых групп по-прежнему имеют доступ, кроме явно заблокированных.
Добавленному пользователю в разрешённой группе доступны клиенты этой группы.

`/start` и `/menu` открывают главное меню. `/clients` открывает список активных
клиентов агентского аккаунта Яндекс Директа, разрешённых текущему чату.
Docker Compose всегда запускает production с автоматической загрузкой клиентов.
Тестовый YAML в этом режиме не читается и не монтируется.

В списке по 8 клиентов на страницу; стрелки обновляют одно сообщение.
Выберите клиента → подробную проверку, краткую сводку или график динамики → период:
вчера, 7, 14, 30 или 90 завершённых дней по Москве.
«Аналитика всех клиентов» запускает тот же выбор отчёта и периода для всех
доступных активных клиентов. Проверки используют общий сервис аналитики и очередь
фоновых заданий, как команды `/check` и `/summary`.

Расписание видно администраторам. Команды и вопросы обычным текстом сохранены.
В mock-режиме меню явно обозначает тестовые данные.

При запуске загружаются все неархивные клиенты через AgencyClients.get с пагинацией.
Администратор может повторить загрузку кнопкой «Обновить клиентов Яндекса».
При ошибке список очищается: тестовые и устаревшие клиенты не подставляются.
Без YANDEX_CLIENT_CHAT_IDS клиенты видны только в личных чатах администраторов,
также включённых в TELEGRAM_ALLOWED_CHAT_IDS. Для общего рабочего чата явно
укажите его в обоих списках. Это открывает ему весь список агентства.

Счётчики находятся при проверке клиента по CounterIds кампаний. Из каждого
счётчика загружаются цели и их достижения за оба периода. Большие запросы
делятся по 100 кампаний и 20 метрик. В подробном отчёте каждая цель показана
отдельно с ID счётчика. Между счётчиками визиты и цели не суммируются.
Если доступа к счётчику нет, отчёт указывает ограничение и сохраняет данные
Директа. Цели не объявляются автоматически уникальными заявками: общий CPA
и CR не рассчитываются без определения основных конверсий. Денежные расчёты
поддерживают RUB; другие валюты отмечаются как несопоставимые.

В списке и отчётах показываются ClientInfo и Client-Login из API рядом.
Если ClientInfo не заполнен, остаётся логин. ClientInfo — подпись аккаунта
в Яндексе; иногда она содержит имя представителя вместо названия компании.
Автообнаружение рассчитано на агентский аккаунт (AgencyClients), как adbeam-ru.
Mock остаётся только для локальных тестов и команды demo.

Кнопки принадлежат пользователю и чату, открывшим меню, и действуют 10 минут.
При переходе старые кнопки пользователя становятся недействительными.
После перезапуска, истечения срока или `/cancel` откройте `/menu` заново.
Права на клиента повторно проверяются при нажатии кнопки.

Обновление сервера: `git pull`, затем `docker compose up -d --build bot`.
После запуска отправьте `/menu`.

Перед запуском расписания и polling бот получает и кеширует getMe.
При сетевом таймауте или временной ошибке Telegram повторяет подключение
с паузами до 30 секунд, не перезапуская процесс. Каждая попытка видна в логах;
на одну попытку getMe отводится 15 секунд. Регистрация меню команд остаётся
отдельной фоновой задачей. Недействительный токен не маскируется повторными попытками.

При ручной проверке бот обновляет одно сообщение примерно раз в 4 секунды:
двигающийся индикатор, прошедшее время и текущий этап. По завершении сообщение
заменяется первым блоком отчёта; продолжение длинного отчёта отправляется отдельно.
Показатели выводятся отдельными жирными строками. Форматирование применяется
через Telegram entities: названия клиентов и текст данных не интерпретируются как HTML.
В журнале сервера видны начало и завершение проверки и запросов к API
(без токенов, заголовков авторизации и тел ответов).
Плановые проверки занимают не более одного из трёх слотов анализа клиентов.
Для краткой сводки ожидание каждого периода Директа ограничено 60 секундами,
последующая загрузка Метрики — 45 секундами. Подробная проверка даёт каждому
источнику до 180 секунд. Эти сроки не включают очередь и доставку в Telegram.
Если Метрика не успела, отчёт сохраняет полученные данные Директа и сообщает
об ограничении; отсутствие данных не трактуется как нулевые конверсии.

График строится по дневному отчёту Директа и отправляется как PNG: карточки расхода,
кликов, конверсий и CPA, а также линии текущего и предыдущего равного периода.
Название клиента и Client-Login показаны вместе. Команда: `/chart <клиент> [период]`.
Он также автоматически отправляется после одиночной проверки клиента и ответа на
аналитический вопрос. Горизонтальная ось подписана датами текущего периода; пунктир
сопоставляет соответствующие по порядку дни предыдущего периода.
