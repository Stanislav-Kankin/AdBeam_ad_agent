# AdBeam Performance Analyst — MVP

Внутренний Telegram-аналитик действующих клиентов AdBeam. Основание — переданный
промпт; встреча использована как контекст продуктовой задачи. Изменение рекламы,
генерация баннеров, SEO-аудит, SaaS-биллинг и веб-панель в этот этап не входят.

## Архитектура

Python 3.12, модульный монолит. aiogram 3 принимает сообщения; APScheduler 3
запускает ежедневную проверку в 10:00 Europe/Moscow. Оба вызывают единый
CheckService.run_check. Асинхронные HTTP-запросы и ограниченные фоновые задачи
не блокируют обработку команд. Один процесс/реплика long polling на токен бота.

Интеграции → типизированные агрегаты → расчёты и правила → отчёт → Telegram.
DeepSeek через интерфейс LLMProvider вызывает только реестр разрешённых инструментов.
Backend проверяет chat allowlist, доступ к клиенту, даты, top_n и лимит 8 вызовов.
Модель не получает доступ к HTTP-клиенту, БД, окружению или выполнению кода.

SQLAlchemy async хранит запуски, сигналы, отчёты, ошибки, длительность и журнал
инструментов. SQLite по умолчанию; PostgreSQL через asyncpg. Схема — Alembic.
История диалога временная, ограниченная, отдельно для пары чат/пользователь.
Секреты только из окружения/.env, идентификаторы и пороги — из YAML.

## Аналитические соглашения

- Периоды включают обе границы, не более 90 дней, только завершённые дни МСК.
  Вчера сравнивается с тем же днём недели неделю назад; N дней — с предыдущими N.
- Расход, показы, клики и конверсии берутся из Direct Reports с явно заданными
  целями и одной моделью атрибуции. CR = конверсии / клики; это не CR визитов Метрики.
  Сумма нескольких целей — сумма конверсий, а не уникальные лиды/заказы.
- Метрика служит отдельной проверкой визитов и основных целей, с фильтром
  рекламодателя Директа. Её достижения целей не складываются с конверсиями Директа.
- При недоступной аналитике CPA/CR не выдаются за достоверные показатели.
  Учитывается задержка конверсий: сигналы эффективности подавляются для незрелого
  окончания периода; пользователю предлагается повторить проверку позже.
- Выручка ecommerce относится к тому же рекламодателю; Roistat требует явного
  фильтра рекламного канала в YAML. Валюта MVP — RUB, расход без НДС.
  Несопоставимые периоды, валюта или атрибуция исключают расчёт ДРР.
- Бюджетный план пропорционален календарным дням каждого затронутого месяца
  (либо недельному бюджету). Это оценка равномерного расхода, не биллинг.
- Зелёный статус означает «в выполненных проверках сигналов не обнаружено».
  Нет данных, недоступный источник и невыполненная проверка имеют отдельные статусы.
- Драйверы — вклад кампаний в абсолютное изменение расхода и конверсий;
  это не доказательство причинности изменения CPA.

## План реализации

1. Конфигурация, доменные модели, периоды, метрики, стабильные mock-данные.
2. Общая диагностика, отчёты, журнал и Telegram-команды.
3. Реестр инструментов, DeepSeek и fallback без LLM.
4. Официальные Direct/Метрика/Roistat API, расписание.
5. Тесты, Ruff, Docker/Compose, инструкции и проверка запуска.

## Развёртывание

Docker на сервере, исходящие HTTPS-соединения, без публичных портов и SSL-сервера.
Volume /app/data хранит SQLite. Конфиг подключается read-only, .env не входит в образ.
Миграции выполняются перед запуском. Production никогда не подменяет ошибку API
mock-данными. Mock маркирует все отчёты и хранит историю отдельно.
