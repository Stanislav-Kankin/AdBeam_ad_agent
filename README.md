# AdBeam Performance Analyst

## Дневное хранилище аналитики

В production бот в фоне сохраняет полные снимки Директа и Метрики отдельно по
клиенту и календарному дню. Сбор начинается со вчерашнего дня и постепенно идёт
назад. После перезапуска контейнера уже собранные дни не загружаются повторно.
Если для запрошенного периода сохранены все дни, бот складывает отчёт из базы без
повторного ожидания API Яндекса.

По умолчанию глубина составляет 30 дней, а между заданиями выдерживается 120
секунд. Параметры `WAREHOUSE_ENABLED`, `WAREHOUSE_BACKFILL_DAYS` и
`WAREHOUSE_INTERVAL_SECONDS` можно изменить в `.env`. Уникальных посетителей за
несколько дней бот не складывает: сумма дневных значений завысила бы аудиторию.

Серверный Docker Compose запускается только в боевом режиме: список клиентов
загружается из агентского аккаунта Директа по `DIRECT_OAUTH_TOKEN`.
Ручное заполнение `config/clients.yaml` для этого режима не требуется.
Откройте `/menu` → «Клиенты». Администратору доступно обновление списка из Яндекса.
Настройка прав, автоматическое обнаружение счётчиков и ограничения анализа
описаны в [инструкции меню](docs/telegram-menu.md).

Внутренний Telegram-аналитик рекламных кампаний AdBeam. Проверяет клиентов по
расписанию и по командам, отвечает на вопросы через DeepSeek Tool Calls. Все
расчёты выполняет Python. Рекламу, ставки, бюджеты и объявления бот не изменяет.

Есть полностью локальная демонстрация без ключей, mock-бот и адаптеры официальных
API Директа, Метрики и Roistat. Для работы с реальными данными нужны ваши доступы.

## Быстро посмотреть результат без ключей

Python 3.12, команды из корня репозитория. Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.lock
.\.venv\Scripts\python -m pip install --no-deps -e .
.\.venv\Scripts\python -m app.main demo
.\.venv\Scripts\python -m app.main demo --client west_export --period 14d
.\.venv\Scripts\python -m app.main demo --ask "Почему у West Экспорт вырос CPA?"
.\.venv\Scripts\python -m app.main demo --daily
```

Linux/macOS:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
.venv/bin/python -m pip install --no-deps -e .
.venv/bin/python -m app.main demo
```

`demo` всегда использует синтетические данные и отдельную `data/adbeam_demo.db`.
В Telegram ничего не отправляется. West — красный сценарий с расходом без
конверсий в РСЯ, Grand Line — жёлтый с ростом CPC, Fresh Parfum — зелёный.
Данные повторяемы, согласованы для пересекающихся периодов и привязаны к дате
старта процесса. В режиме без ключа свободные вопросы разбирает простой
демонстрационный обработчик: он показывает последовательные вызовы инструментов,
но не заменяет DeepSeek и понимает ограниченный набор формулировок.

Один реальный вопрос DeepSeek на mock-данных, без Telegram: после настройки
`DEEPSEEK_API_KEY` в локальном `.env` запустите:

```powershell
.\.venv\Scripts\python -m app.main demo --live-llm --ask "Почему у West Экспорт вырос CPA?"
```

Только этот флаг включает платные запросы в консольной демонстрации. Обычный
`demo` не использует ключ. В ответе рекламные данные остаются явно отмечены MOCK.

## Запустить Telegram-бота

1. Скопируйте `.env.example` в `.env`, а `config/clients.example.yaml` в
   `config/clients.yaml` (`Copy-Item` в PowerShell, `cp` в Linux).
2. Создайте бота через [@BotFather](https://t.me/BotFather), запишите токен в
   `TELEGRAM_BOT_TOKEN`. Добавьте бота в рабочую группу.
3. Укажите ID группы в `TELEGRAM_ALLOWED_CHAT_IDS`, `TELEGRAM_REPORT_CHAT_ID` и
   в `telegram.allowed_chat_ids` каждого доступного этой группе клиента.
   У супергрупп ID обычно отрицательный. Разрешены только чаты из обоих списков.
4. В `TELEGRAM_ADMIN_USER_IDS` укажите ID сотрудников, которым доступна `/schedule`.
   Пустой список не даёт эту команду никому. Для определения ID можно использовать
   собственного бота и официальный `getUpdates` до запуска polling; не публикуйте токен.
5. Для получения обычных сообщений группы отключите privacy mode через
   `/setprivacy` в BotFather; при необходимости удалите и повторно добавьте бота.
   См. [FAQ Telegram о сообщениях групп](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).
6. Сначала оставьте `APP_MODE=mock`. Чтобы проверить настоящие Tool Calls на
   синтетических рекламных данных, добавьте `DEEPSEEK_API_KEY`.

```powershell
.\.venv\Scripts\python -m app.main validate-config
.\.venv\Scripts\python -m app.main bot
```

На Linux замените путь на `.venv/bin/python`. Миграции применяются автоматически
перед запуском. Отдельная команда миграций: `python -m app.main migrate`.

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Помощь |
| `/clients` | Активные доступные клиенты |
| `/check_all [period]` | Стандартная проверка всех доступных клиентов |
| `/check <client> [period]` | Подробная проверка клиента |
| `/summary_all [period]` | Основные показатели всех клиентов |
| `/summary <client> [period]` | Краткий отчёт по клиенту |
| `/chart <client> [period]` | PNG-график дневной динамики и сравнение периодов |
| `/schedule` | Состояние, время, чат, последний и следующий запуск; только администраторы |
| `/cancel` | Отменить выбор клиента и очистить контекст текущего пользователя |

Примеры: `/check west_export`, `/check "West Экспорт" 14d`,
`/summary grand_line 30d`, `/chart "Grand Line" 30d`, `/check_all yesterday`. Клиент определяется по ID,
имени или алиасу. При неоднозначности бот предлагает кнопки. Выбор привязан к
пользователю, сохраняет команду и период, истекает через 10 минут.

К одиночным `/check`, `/summary`, проверкам из меню и аналитическим вопросам
обычным текстом бот автоматически прикладывает график. Для общей проверки всех
клиентов графики не создаются, чтобы не отправлять десятки изображений.

Вопросы: «Почему у West Экспорт вырос CPA?», «Посчитай ДРР по Fresh Parfum за
14 дней», «Проверь площадки РСЯ по West». Диалог изолирован по чату и пользователю;
активный клиент, последний период и шесть последних реплик хранятся в базе и
переживают рестарт. `/cancel` очищает этот контекст, но не прерывает уже запущенную
проверку. Пока проверка выполняется, остальные пользователи могут работать.

В production администратор может открыть клиента в `/menu` → «Данные и цели»,
обновить список связанных счётчиков, выбрать один или несколько доступных
счётчиков и до 10 основных целей. Выбор хранится в базе и применяется после
повторного обнаружения клиентов и перезапуска контейнера.

## Доступы и переменные окружения

Секреты храните в `.env` на машине запуска. Он исключён из Git и Docker-образа.
Ключи не передаются модели. В YAML указываются только имена переменных для секретов.

| Переменная | Назначение |
| --- | --- |
| `APP_MODE` | `mock` или `production` |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather, обязателен для команды `bot` |
| `TELEGRAM_ALLOWED_CHAT_IDS` | JSON-массив ID, например `[-1001234567890]` |
| `TELEGRAM_ADMIN_USER_IDS` | JSON-массив ID администраторов |
| `TELEGRAM_REPORT_CHAT_ID` | Единственный чат ежедневной доставки |
| `CLIENTS_CONFIG` | По умолчанию `config/clients.yaml` |
| `DEEPSEEK_API_KEY` | Ключ DeepSeek для свободных вопросов |
| `DEEPSEEK_BASE_URL` | По умолчанию `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | По умолчанию `deepseek-v4-flash`; укажите доступную модель с Tool Calls |
| `DIRECT_OAUTH_TOKEN` | OAuth агентского аккаунта Директа |
| `METRICA_OAUTH_TOKEN` | OAuth с правом чтения Метрики |
| `ROISTAT_API_KEY` | Нужен только для клиентов с `revenue.source: roistat` |
| `SCHEDULE_ENABLED` | `true` / `false` |
| `SCHEDULE_HOUR`, `SCHEDULE_MINUTE` | По умолчанию `10`, `0`, всегда Europe/Moscow |
| `MOCK_SCHEDULE_INTERVAL_SECONDS` | Тестовый интервал вместо cron; `0` выключен, разрешён только в mock |
| `DATABASE_URL` | По умолчанию SQLite: `data/adbeam_mock.db` или `data/adbeam_production.db` |
| `HTTP_TIMEOUT_SECONDS`, `HTTP_RETRIES` | По умолчанию 30 секунд и 4 повтора |
| `MAX_BACKGROUND_JOBS` | По умолчанию 4; один запрос одновременно на пользователя в чате |
| `LOG_LEVEL` | По умолчанию `INFO` |

**Директ.** Зарегистрируйте приложение и оформите доступ к Direct API по
[официальной инструкции](https://yandex.com/dev/direct/doc/en/steps).
Получите OAuth для аккаунта, имеющего доступ к нужным рекламодателям. Для агентского
аккаунта задайте `direct.client_login` отдельно для каждого клиента: он идёт в
заголовок `Client-Login`. В приложении реализованы только чтение Campaigns `get`
и Reports; полный OAuth scope провайдера сам по себе не добавляет операций записи.

**Метрика.** Используйте приложение Яндекс OAuth с правом `metrika:read` и
пользователя с доступом к счётчику. Счётчики и основные goal ID можно задать в
YAML либо выбрать в административном меню бота. Часовой пояс счётчика —
`Europe/Moscow`.
Инструкция: [авторизация API Метрики](https://yandex.com/dev/metrika/en/intro/authorization).
Используются только Reporting и чтение настроек/целей Management API, без Logs API.

**DeepSeek.** Создайте ключ в [кабинете DeepSeek](https://platform.deepseek.com/).
Base URL и модель настраиваются; SDK OpenAI используется как клиент совместимого
Chat Completions API. [Документация Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/).
Используется простой цикл без LangChain/LangGraph. JSON Schema с запретом лишних
полей и строгая Pydantic-валидация выполняются в backend. Серверный beta strict
mode не требуется. В запросе явно отключён thinking mode. Старые имена
`deepseek-chat`/`deepseek-reasoner` объявлены устаревшими с 24 июля 2026 года:
[модели DeepSeek](https://api-docs.deepseek.com/quick_start/pricing).

**Roistat.** Получите API-ключ и project ID в аккаунте Roistat. Настройте
явный фильтр рекламного канала, затем подтвердите валюту RUB и сопоставимость
атрибуции с расходами. [Официальный агрегированный Analytics API](https://help-en.roistat.com/API/methods/analytics/).
Запрашивается только `revenue`, без карточек сделок и лидов.

```yaml
revenue:
  source: roistat
  roistat_project_id: 12345
  token_env: ROISTAT_WEST_API_KEY
  currency: RUB
  attribution_confirmed: true
  roistat_filters:
    - field: marker_level_1
      operator: '='
      value: YOUR_YANDEX_CHANNEL
```

Значение фильтра берётся из вашего проекта, не из примера. Секция
`attribution_confirmed: true` — явное подтверждение аналитика, а не автоматическая
проверка модели. Для ecommerce Метрики также включайте её только после сверки
выручки. Без подтверждения выручка может быть показана отдельно, ДРР не считается.

## Добавить клиента

Добавьте запись в `config/clients.yaml` по примеру. Обязательны уникальный `id`,
имя, `direct.client_login`, `metrica.counter_id` и `telegram.allowed_chat_ids`.
Настройте одинаковый набор `main_goal_ids` для Директа и Метрики. Если цели не
указаны, бот выдаст техническое предупреждение вместо вывода об эффективности.

У каждого клиента свои `target_cpa`, `target_drr`, бюджет и пороги. По умолчанию
задержка конверсий 3 дня; **в демонстрационном YAML она равна нулю для наглядности**.
Перед production задайте реальную задержку клиента. Для отдельных токенов используйте
`direct.token_env`, `metrica.token_env`, `revenue.token_env` и соответствующие
переменные в `.env`. Секреты внутри YAML запрещены схемой.

`active: false` исключает клиента из команд и расписания. Ошибочная запись
пропускается с сообщением в журнале; другие клиенты продолжают работать. Повторяющиеся
ID исключаются целиком. `validate-config` возвращает ненулевой код при ошибках.
После изменения YAML или `.env` перезапустите бота.

## Docker на сервере

Нужны Docker Engine и Compose v2. Приложение работает через long polling: входящие
порты, домен и SSL не нужны. Требуется исходящий HTTPS к Telegram, Яндексу,
DeepSeek и при необходимости Roistat. Одна реплика на токен Telegram.

```bash
cp .env.example .env
cp config/clients.example.yaml config/clients.yaml
# Заполните локальные .env и clients.yaml, сначала APP_MODE=mock.
chmod 600 .env
docker compose build
docker compose run --rm bot validate-config
docker compose up -d
docker compose logs --tail=100 -f bot
docker compose ps
```

Контейнер работает под UID 10001. SQLite находится в именованном volume
`adbeam_data`; YAML монтируется только для чтения. На сервере файл YAML должен
быть читаем UID 10001. Секретов в нём нет. `.env` передаётся контейнеру через
Compose. Healthcheck проверяет, что процесс обновляет heartbeat; доступность
рекламных API отражается в отчётах, а не в этом healthcheck.

Проверка Docker без ключей, `.env` и конфигурации сервера:

```bash
docker build --target runtime -t adbeam-analyst:local .
docker run --rm adbeam-analyst:local demo
docker run --rm adbeam-analyst:local demo --ask "Проверь West Экспорт"
```

Обновление после получения нового кода: `docker compose up -d --build`.
Миграции применяются при старте. Перед обновлением храните резервную копию
SQLite; для согласованной копии используйте SQLite backup API или остановите
бота и скопируйте весь каталог `data` вместе с WAL-файлами. `docker compose down`
сохраняет volume; **`down -v` удаляет историю**.

PostgreSQL поддерживается через
`DATABASE_URL=postgresql+asyncpg://user:password@db:5432/adbeam`.
Базу/роль нужно создать заранее. Миграции одинаковы, существующие данные SQLite
не переносятся автоматически. Не публикуйте эту строку подключения в логах.

## Расписание и история

В 10:00 МСК проверяются вчера против того же дня недели неделю назад и последние
7 завершённых дней против предыдущих 7. `/check_all` без периода проверяет 7 дней.
Текущий день не входит в расчёт. После рестарта позже 10:00 пропущенный запуск
за текущий день выполняется автоматически; старые дни не догоняются.

Доставка сохраняет части отчёта и отметки их отправки. Неоконченная доставка за
текущий день повторяется раз в 5 минут. При падении между успешной отправкой в
Telegram и фиксацией в БД одна часть может повториться: Telegram не предоставляет
идемпотентный ключ отправки. Уже завершённая доставка не повторяется. Изменение
списка доступных клиентов создаёт новый отчёт, исключая отправку устаревшего доступа.

Таблицы: `check_runs` (периоды, клиенты, сигналы, отчёты, ошибки, длительность),
`tool_events` (валидированные вызовы, отказ/ошибка), `deliveries` (части доставки).
OAuth/API-ключи не хранятся. Автоматическая очистка истории пока не добавлена.

## Проверки

```powershell
.\.venv\Scripts\pytest -q
.\.venv\Scripts\ruff check app tests migrations
.\.venv\Scripts\ruff format --check app tests migrations
```

В Linux-контейнере:

```bash
docker build --target test -t adbeam-analyst:test .
docker run --rm adbeam-analyst:test
```

Тесты покрывают арифметику, периоды, пороги, пропавшую аналитику, изоляцию клиентов,
валидацию и лимит инструментов, ошибки LLM, API через HTTP-заглушки, Telegram
через тестовую сессию, кнопки, фоновые задачи, расписание и повторную доставку.
Они не требуют реальных ключей и не отправляют сообщения в Telegram.

## Ограничения MVP

- Реальные API требуют проверки с доступами клиента и сверки с кабинетами.
- Только RUB, расход без НДС; CR — конверсии на клик. Несколько основных целей
  суммируются как конверсии, не уникальные лиды. Для CPO выберите одну цель покупки.
- Свежие периоды с задержкой конверсий показывают предварительные цифры;
  сигналы CPA/CR и расхода без конверсий подавляются до созревания данных.
- Проверка аналитики выявляет признаки проблем; она не выполняет тестовую
  отправку формы и не доказывает корректность установки счётчика.
- Цели и показатели поведения Метрики показываются по выбранному счётчику целиком;
  конверсии Директа остаются ограничены рекламным аккаунтом. Эти области явно
  подписываются и не суммируются между собой.
- Direct Reports загружается страницами по 10000 строк до защитного предела
  1 000 000 строк. `top_n` в ответе ограничен 50 строками, ответ инструмента —
  40000 символами; полный снимок сохраняется в базе.
- Диалог модели: максимум 8 вызовов, 240 секунд, периоды до 90 дней. Увеличение
  лимита периода через подтверждение пока не реализовано.
- `/check`, `/summary`, меню и расписание передают готовые расчёты DeepSeek для
  редакторского анализа. При недоступности модели отправляется детерминированный
  отчёт; причинность остаётся гипотезой.
- Текстовые поисковые запросы агрегированы; известные секреты, email и форматы
  телефонов маскируются. Это не универсальный детектор всех персональных данных.
- Один процесс без веб-панели, RAG и изменений рекламы. Снимки и контекст хранятся
  в SQLite/PostgreSQL; неполные снимки кешируются 10 минут, завершённые — дольше.

Архитектура и аналитические соглашения: [docs/mvp.md](docs/mvp.md).
Следующий этап — внутренний пилот на 1–2 клиентах: сверка целей, атрибуции,
бюджетов и порогов с Андреем/аналитиком, оценка полезности сигналов и ложных тревог.
